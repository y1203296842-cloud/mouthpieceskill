# references/memory.md — 用户记忆系统规范

> 用户记忆与知识库**完全分离**。这里管理：表达风格、偏好、雷区、人物、事件、反馈、候选记忆。
> 版本：`memory_version = 1`。

## 一、目录结构

```
memory/
├── user/
│   ├── style.md          # 用户实际表达风格（行为记录，非空洞人格画像）
│   ├── preferences.md    # 用户偏好
│   └── taboos.md         # 用户雷区（绝对别做）
├── people/               # 一个人一个文件（张三.md）
├── events/               # 一个事件一个文件（YYYY-MM-DD-标题.md）
├── feedback/             # 反馈学习记录（YYYY-MM-DD-*.md）
└── candidates/           # 候选记忆（等待多次验证 → 提升为稳定）
```

## 二、用户风格记忆（style.md）——写行为，不写人格

重点记录**实际行为**，例如：
- 用户喜欢：短、直接、不拖泥带水、不要 AI 味、有力度、根据关系调整强度。
- 用户不喜欢：说教、"我理解你的感受"、大段解释、官方客服口吻、过度礼貌、网络烂梗堆砌。
- 可观察行为：用户经常把 AI 长回复改短 / 经常选更冷淡版本 / 经常删客套话。

## 三、人物记忆（people/张三.md）

```yaml
---
name: 张三
relation: <同事/朋友/亲戚/crush/领导…>
since: <认识时间>
---
```

记录：身份、历史事件引用、说话习惯、用户对他的态度、用户希望的沟通距离、过去冲突、过去成功/失败回复。

> 用户一句"张三又来了"，就应能召回相关历史与人物文件。

## 四、事件记忆（events/YYYY-MM-DD-标题.md）

记录：发生了什么、涉及谁、用户怎么处理、结果、什么回复有效。
事件与人物建立引用关系（互相链接文件名）。

## 五、候选记忆与提升（candidates/）

生命周期：
```
当前上下文 → 候选记忆 → 置信度 → 多次验证 → 稳定记忆
```
- 候选写 `memory/candidates/`，带 `confidence`（候选时低）。
- 同一候选反复出现 / 用户反复确认 → 提升为稳定记忆，写 `user/people/events`。
- **用户明确说"记住这个" → 立即正式保存**，跳过候选。
- 详见 `references/learning.md`。

## 六、检索
- 用户风格/人物/事件在生成前按优先级检索（见 SKILL.md Step 2）。
- 人物与事件、用户偏好与知识案例是**分开检索、分开存放**的。
