# references/learning.md — 学习循环与反馈信号

> 吸收自 HelloRuru/claude-memory-engine 的"学习循环"思路，但**刻意克制**：
> 系统每轮聊天不随便改长期记忆，只有候选 → 置信度 → 多次验证 → 稳定 才落盘。

## 一、用户反馈是核心训练信号

| 用户行为 | 学习信号 |
|---|---|
| AI 给 A/B/C，用户选 B | 记录偏好：B 的类型/语气/强度更被接受 |
| 用户"B 但把最后一句改成 XXX" | 喜欢这个结构，但不喜欢这个词 |
| 用户"太像 AI 了" | 分析到底哪里像 AI，定位具体句式/长度/口吻 → 候选 taboo |
| 用户反复选同一风格 | 候选 → stable preference |
| 用户明确"记住这个" | **立即正式保存**，跳过候选 |

## 二、候选 → 置信度 → 稳定

- 新观察写 `memory/candidates/`，`confidence: candidate`。
- 同一信号再次出现（被用户重复确认/再次选择）→ `confidence` 提升。
- 达到阈值（默认：同一候选被再次确认 ≥ 2 次，或用户明确要求）→ 提升为稳定记忆，
  写入 `memory/user/`（style/preferences/taboos）或 `people/`、`events/`。
- 候选保留在 candidates 留痕，被提升后从活跃候选移除（可标记 `promoted: true`）。

## 三、知识库的持续学习（不是不断加案例，而是收敛成规律）

```
新增案例 → 统计模式 → 发现重复策略 → 抽象共同规律 → 更新 strategy
```

- 新增案例入库后，比对 `strategies/`：若新案例体现已有策略，只把 case 加入该 strategy 的 `examples`。
- 若一批新案例共同体现一个**尚未抽象**的规律，才新建一条 strategy。
- 例如经过很多"对方贴标签"的案例，可抽象出策略 `reverse-premise`（不接对方前提）。
- 旧策略不准确 → 可更新，但保留 `change_log`。

## 四、不动长期记忆的克制
- 每轮聊天产生的是**上下文**，不是**记忆**。
- 只有：用户明确要求 / 同一信号反复验证 / 涉及人物事件的重要事实 才写长期记忆。
- 一次性指令（"这次用这个"）不写长期记忆。

## 五、版本
- 记忆版本：`memory_version = 1`。
- 每次提升/更新在目标文件的 `updated` 字段留痕。
